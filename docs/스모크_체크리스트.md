# 스모크 체크리스트 — 눈으로만 확인되는 것들

자동 테스트가 못 가는 자리를 모아둔다. 플레인 node 스위트는 DOM·`rAF`·카메라·CSS에
접근하지 못하므로, 그 경계 밖의 동작은 여기 적어두고 배포 전에 한 번씩 눈으로 본다.

**기록에 맡기지 않는 이유:** 이런 항목은 "깨져도 조용하다". 타이머가 2배속으로 흐르거나
권한 프롬프트가 하나 더 뜨는 건 예외도 로그도 남기지 않는다. 목록이 없으면 다음 사람이
(대개 두 달 뒤의 우리) 같은 자리를 다시 발견하는 데 컨텍스트 복원 비용을 낸다.

확인 방법: `python -m http.server 8137` → `http://127.0.0.1:8137/`

> ⚠ 브라우저 자동화로는 `rAF` 기반 동작을 확인할 수 없다. 자동화 탭은
> `document.visibilityState === 'hidden'`이라 `requestAnimationFrame`이 한 번도 안 돈다
> (포커스를 줘도 그렇다). 진행 바가 **차오르고 리셋되는** 것, timed 라운드가 넘어가는 것은
> 사람이 직접 창을 띄워 봐야 한다. 반대로 DOM 존재·레이아웃·`getUserMedia` 호출 여부는
> 자동화로 확인된다 — 아래 체크는 그 경계를 염두에 두고 나눠 적었다.

- [ ] 양쪽 끝을 한 번씩 찍으면 카운트가 1 오른다. 한쪽만 왕복해서는 안 오른다.

## 실측이 필요한 임계값

전부 기하학 추정치라 실기기에서 한 번에 확정한다.

### ★맨 먼저 — 오른손 부호 확인 (30초)

아래 임계들보다 이걸 먼저 한다. 남은 항목 중 **결과에 따라 나머지의 우선순위가 바뀌는
유일한 것**이라, 순서를 지키면 헛수고를 안 한다.

- [ ] `config.DEBUG_GUIDE = true` → **오른손**으로 손목을 굽힌다 → 콘솔 `[flexExt] rel=…`의
      부호를 본다. **양수로 나오면 아래 추론이 사실이다.**

`flexExtRel(rel, hand) = hand === 'right' ? -rel : rel`이 존재한다는 건 같은 동작이 손에 따라
화면 부호가 반대라는 뜻이다. 그런데 `flexExtDetector`는 그 화면 부호에 **비대칭** 임계를 건다
(`range = { lo: -flexT(24), hi: extT(12) }`). 그래서 굽힘/폄에 요구되는 각도가 손마다 뒤바뀐다 —
왼손은 굽힘 24°·폄 12°(의도대로), **오른손은 굽힘 12°·폄 24°**. `extT`를 낮게 둔 이유가
*"폄은 2D 카메라가 덜 본다"* 인데, 오른손에서는 그 보정이 거꾸로 걸린다.

**완주 성립 자체는 양손 다 된다** — 양 끝을 모두 요구하므로 README의 "왼손/오른손 어느 쪽이든
동일하게 동작"은 그 뜻에서 맞다. 틀어지는 건 **방향별 난이도**다. 사실로 확인되면 임계를 화면
부호가 아니라 해부학적 방향에 걸어야 하고, 그 수정이 아래 비율 임계 실측보다 우선한다.

### 비율 임계 6개

- [ ] `VIEW_FIT.sideMax` (0.45) / `frontMin` (0.60) — 두 값 사이 완충 구간은 경계에서
      게이트가 깜빡이는 걸 막는 히스테리시스다. 실측 후에도 이 구조는 유지할 것.
- [ ] `fingerSpreadDetector`의 `openT` (1.15) / `closeT` (0.95).
- [ ] 〃 `extendedT` (1.45) — 위 둘과 성격이 다르다. 벌림/모음을 **세는** 임계가 아니라 판정
      자체를 **여는 게이트**다(손가락을 굽혀도 손끝 폭은 줄어서 '모음'으로 오인되기 때문).
      너무 높게 잡으면 제대로 하는 사람의 카운트가 통째로 안 올라간다 — 조용한 고장이라
      반드시 같이 잰다. `fingerSpread:grip`은 게이트 **앞에서** 기록되므로 `__rec` 표에 그대로 나온다.
- [ ] `thumbOppositionDetector`의 `touchT` (0.35) — 합성 기하 기준 접촉 0.03 · 3cm 근접 0.32 ·
      손 편 상태 1.1~1.35. 이웃 손가락 끝 간격이 0.3 안팎이라 여유가 크지 않다(최근접
      조건이 그 좁은 여유를 메운다). 실측에서 이웃 간섭을 특히 볼 것.

### 절차 — 분포로 정한다

프레임 로그를 눈으로 훑어서 최대·최소를 줍는 방식으로는 임계를 정할 수 없다. 그렇게 정한
값은 "내가 본 몇 프레임"에만 맞고 꼬리를 못 본다. `js/debugRec.js`가 자세별 분포를 모은다 —
평소엔 꺼져 있고 소스를 고칠 필요도 없다(`DEBUG_*` 플래그와 무관).

`python -m http.server 8137` → `http://127.0.0.1:8137/` → 콘솔:

```js
__rec.on()        // 기록 시작
// … 아래 셋을 수행 …
__rec.report()    // 키별 n / min / p5 / p50 / p95 / max 표
__rec.dump()      // 원자료 JSON — 임계 결정을 남에게 맡길 때 통째로 넘긴다
```

1. **손목 체크** — 옆모습 단계에서 굽힘·폄 왕복, 정면 편위 단계에서 좌우 왕복.
   각 단계를 **제대로 된 자세로** 30초쯤. → `view:side` · `view:front`
2. **손가락 벌리기** 가이드 — 활짝/모음 왕복 10회 이상. → `fingerSpread:fanSpan` · `:grip`
3. **엄지 대립 순환** 가이드 — 검지~새끼 두 바퀴, 그리고 손을 쫙 편 채로 몇 초.
   (편 상태 값이 있어야 접촉값과의 분리도를 본다.) → `thumbOpp:검지…새끼`

### 읽는 법

| 상수 | 근거로 쓸 값 | 두는 자리 |
|---|---|---|
| `VIEW_FIT.sideMax` (0.45) | `view:side`의 **p95** | 그 위 — 옆모습을 제대로 한 프레임의 95%가 통과해야 |
| `VIEW_FIT.frontMin` (0.60) | `view:front`의 **p5** | 그 아래 |
| `fingerSpreadDetector.openT` (1.15) | `fingerSpread:fanSpan`의 **p95** | 조금 아래 |
| 〃 `closeT` (0.95) | 같은 키의 **p5** | 조금 위 |
| 〃 `extendedT` (1.45) | `fingerSpread:grip`의 **p5** | 그 아래 (게이트가 정상 수행을 막으면 안 된다) |
| `thumbOppositionDetector.touchT` (0.35) | `thumbOpp:*`의 **손가락별 min 중 가장 큰 값** | 그 위, 그리고 편 손 값(max)보다 한참 아래 |

- **두 값이 겹치면 완충 구간을 없애지 말 것.** `view:side`의 p95가 `view:front`의 p5보다
  크면 임계를 붙이지 말고 두 자세를 다시 재라 — 겹친다는 건 자세 안내가 안 통했다는 뜻이고,
  임계로 덮으면 게이트가 경계에서 깜빡인다(그 구간이 히스테리시스인 이유).
- **`touchT`는 새끼가 정한다.** 대립 각도가 가장 커서 min이 제일 크게 나온다.
- **이웃 간섭:** 검지에 댔을 때 `thumbOpp:중지`가 touchT 아래로 들어오는지 본다. 들어와도
  판정기는 '최근접' 조건으로 막지만, 여유가 얼마나 좁은지는 이 분포에서만 보인다.

> `view:*`는 DOM·카메라 경로라 자동 확인이 안 된다. 나머지 두 판정기의 기록 배선은
> 헤드리스로 확인했다(게이트 앞뒤로 표본 수가 갈리는 것까지).

### 각도 재검사 변동 — `ROM.stableBand` (7°)

위 임계들과 달리 비율이 아니라 각도이고, 분포가 아니라 **같은 사람의 같은 날 재검사 폭**이라
`__rec` 없이 잰다. 결과 화면의 숫자만 적으면 된다.

- [ ] **손목 체크를 연속 4회** 하고 **첫 회는 버린다.** 나머지 3회의 `flex`/`ext` 각각
      최대−최소가 재검사 변동이다. 첫 회를 버리는 이유: 오랜만에 하면 워밍업 효과로 낮게
      나와 변동 폭이 실제보다 크게 잡힌다.

이 한 값이 두 곳을 동시에 움직인다 — 유지 타이머 리셋(`measurement.js`)과, 거기서 파생되는
판정 문턱 `SIGNAL_DEG = stableBand + 1`(`config.js`). 문턱은 red(순한 코스 발동)와
improve(칭찬 표시) 양쪽이 같이 쓴다. **그래서 실측 뒤에는 `stableBand` 한 곳만 고친다.**

지금 값(7°)은 프로토타입(`wrist-garden_32.html` L1138)에서 주석 없이 이식된 맨 상수라 근거
기록이 없다. 변동이 실제로 10° 이상이면 지금 순한 코스가 노이즈에 오발동 중이고, 5° 이하면
진짜 하락을 놓치는 중이다 — 어느 쪽이든 지금은 모른다는 게 문제다.

## 화면 낭독기 (NVDA · VoiceOver)

`#srLive`에 글자가 들어가는 것까지는 자동으로 확인했다(화면 전환·모달·데이터 관리).
**실제로 소리가 나는지, 그리고 시끄럽지 않은지는 사람만 안다.**

- [ ] 탭을 옮기면 "기록 화면"처럼 어디로 왔는지 읽는다.
- [ ] **timed 스트레칭(카메라 불필요)을 눈 감고 끝까지 할 수 있다** — 스텝이 바뀔 때
      할 일을 읽어 주고, 라운드가 오를 때 "1/2회"를 읽고, 끝나면 끝났다고 말한다.
- [ ] ★**운동 중에 낭독기가 쉴 새 없이 떠들지 않는다.** 힌트·진행 바는 프레임마다
      바뀌므로 절대 읽히면 안 된다 — 읽힌다면 어딘가에 aria-live가 잘못 붙은 것이다.
- [ ] 도감에서 별자리를 열면 카드 내용이 읽히고, 닫으면 포커스가 **그 별자리로** 돌아온다
      (목록 처음이나 문서 맨 위로 튀지 않는다).
- [ ] 카메라를 막은 채 운동을 시작하면 오류 안내를 즉시 읽는다(`#srAlert`, 하던 말을 끊음).
- [ ] 데이터 관리에서 내보내기·복원·삭제 결과 문구가 읽힌다.

## 폰 앱 껍데기 (실기기)

폰(≤620px)은 문서가 아니라 앱 껍데기다 — 얇은 헤더 / 화면에 맞는 본문 / **하단 고정 탭**.
홈만 무스크롤이고 나머지 화면은 스크롤한다. iframe으로 폭·높이는 쟀지만 아래는 실기기에서만
드러난다.

- [ ] **주소창이 접혔다 펴져도 하단 탭이 화면 밖으로 나가지 않는다** — `100dvh`를 쓴 이유다.
      `vh`는 주소창을 안 따라가서 탭이 잘리거나 아래가 잘린다.
- [ ] 아이폰에서 **홈 인디케이터가 탭 글자를 가리지 않는다**(`safe-area-inset-bottom`).
- [ ] 탭 **5칸**(390px에서 개당 약 71px, 사이 여백 5px)에서 글자가 안 깨지고 오탭이 안 난다.
      ★6칸일 때는 360px을 60px씩 정확히 나눠 가져 **여백이 0**이었다 — 빗나간 탭이 아무 일도
      안 하는 게 아니라 이웃 화면으로 데려갔다. 손목 체크를 빼고 여백을 준 뒤라, 볼 것은
      "여백이 실제로 오탭을 줄이는가"다.
- [ ] **손목 체크로 갈 수 있다.** 탭에서 뺐으므로 폰의 진입로는 홈의 안내 줄
      (`📊 이번 주 손목 체크 …`) 하나뿐이다. 이 줄은 체크를 이미 한 주에도 문구만 바뀌고
      **사라지지 않는다** — 사라지면 주 1회 기능에 아예 못 간다.
- [ ] **홈이 스크롤되지 않는다.** 헤더 액자를 걷은 뒤 여유가 작은 폰(360×667)에서
      6px → **63px**로 늘었다(iframe 측정). 그래도 폰트·기기에 따라 다르니 넘치면
      별자리 판(`.sky-stage` 높이)부터 줄인다 — 높이별로 세 값이다(기본 150 / ≥760px 212 / ≤700px 125).
- [ ] [아래로 더 보기]를 누르면 리마인더·안전 안내·최근 기록이 나오고, 접으면 다시 한 화면.
      ★이 손잡이가 없으면 **폰에서 알림 설정에 갈 방법이 아예 없다**(홈에만 있는 진입점).
- [ ] 낭독기로 하단 탭을 훑으면 "루틴"이 아니라 **"오늘의 루틴"** 으로 읽힌다(`aria-label`).
      보이는 글자는 폭 때문에 줄였지만 읽는 이름은 줄이지 않았다.

### 홈 개편 (2026-09-10) — 눈으로 볼 것

헤더 액자(제목 띠·한마디 상자 약 112px)를 걷고 그 자리를 안내 두 줄이 쓰게 바꿨다.
문구는 하나도 안 지웠다 — 한마디는 액자만 벗고 워드마크 아래로 내려왔다.

- [ ] 인사줄이 **한 줄**이다(마스코트 옆에 문구). 세로로 쌓이면 CSS가 안 먹은 것이다.
- [ ] 별자리 이름이 그림 **위**에 있다(폰에서는 `.box-head`가 숨어 여기가 카드 제목 자리다).
- [ ] 회색 진행 바가 폰 홈에 **없다**. 숫자(`6개 운동 · 약 3분`)는 남는다.
- [ ] ★**별자리가 아무것도 안 켜진 상태에서도 형태로 읽힌다.**
      `.sky-link` 불투명도를 `.10 → .26`으로 올린 결과다. 페가수스자리는 별이 4개뿐이라
      선이 안 보이면 흩어진 점으로 읽혔다 — 거기서 확인하는 게 가장 확실하다.
- [ ] 안내 첫 줄이 **오늘 실제로 되는 게임 이름**을 말한다(코스에 게임이 없는 날은
      "오늘 코스에는 게임이 없어요"). 순한 코스 날에 확인하면 갈린다.

## 좁은 화면 (폰·태블릿)

브레이크포인트는 `max-width:980px` 하나뿐이고, 그 규칙이 **뒤에 온 중복 선언에 덮여
죽어 있던 적이 있다**(2026-09-08). 죽으면 조용하다 — 데스크톱은 멀쩡하고 홈도 멀쩡해서
홈만 열어보면 못 잡는다. 그래서 **홈이 아닌 화면**을 봐야 한다.

- [ ] 폰 폭(≈390px)에서 **오늘의 루틴 · 손목 체크 · 기록 · 게임**이 한 열로 쌓인다.
      두 열로 남으면 오른쪽 칸이 120px대가 되어 "오/른/손"처럼 한 글자씩 세로로 쪼개진다.
- [ ] 가로 스크롤이 생기지 않는다(어느 화면에서도).
- [ ] 데스크톱(≈1200px)은 그대로 — 홈 3열, 나머지 2열.

> 자동화로 재려면 iframe에 앱을 띄우면 된다. 미디어쿼리는 iframe 뷰포트를 따르므로
> 창 크기를 못 바꾸는 환경에서도 폭별 레이아웃을 실제로 확인할 수 있다.

## 배포 메타 (링크를 남에게 보낼 때)

리소스가 200으로 뜨는 것과 미리보기 카드가 실제로 그려지는 것은 다른 문제다. 스크래퍼는
남의 서버에서 돌고 캐시를 오래 쥔다 — 로컬로는 확인할 수 없다. **배포 후** 한 번 본다.

- [ ] 배포본 링크를 슬랙·카카오톡·디스코드에 붙였을 때 **큰 이미지 카드**가 뜬다
      (제목 "오늘의 별자리 — 데일리 손목 웰니스", 밤하늘에 별자리와 고양이).
      안 뜨면 스크래퍼 캐시부터 의심할 것 — og를 고쳐도 한동안 옛 카드가 나온다.
- [ ] 탭에 회색 기본 아이콘이 아니라 **별 아이콘**이 뜬다(`favicon.svg`).
- [ ] iOS Safari "홈 화면에 추가" → 아이콘이 검은 배경 없이 나오고 이름이 "오늘의 별자리".
- [ ] 안드로이드 크롬 "홈 화면에 추가" → 아이콘이 원형으로 잘려도 별이 안 잘린다
      (`icon-maskable-512.png`의 안전 영역).
- [ ] 다크모드에서 주소창 색이 앱 배경과 이어진다(`theme-color` 두 벌).

> ⚠ 설치해도 **알림은 여전히 탭이 열려 있을 때만 간다.** manifest는 아이콘·이름을 줄 뿐
> Service Worker가 아니다. 설치형에서 알림이 오길 기대하게 만들면 리마인더 고지와 어긋난다.

## 데이터 관리 (기록 화면)

체크 기록 목록의 렌더·삭제와 확인창 두 단계는 자동화로 확인했다(2026-09-07: 기록 3건 중
`view:'off'` 1건 → 경고 표식 1개·안내 문구 노출, 가운데 줄 삭제 시 그 기록만 빠지고
focus가 재판정, 취소는 아무것도 안 지움). 아래는 파일 다이얼로그·다운로드·새로고침이라
사람 몫이다.

- [ ] **내보내기가 실제 파일로 떨어진다** — `wrist-garden-backup-YYYY-MM-DD.json`.
      열어서 `kind: "wristGarden.backup"`과 measurements가 들어 있는지 눈으로 본다.
- [ ] **불러오기 왕복** — 내보내기 → 전체 삭제 → 그 파일 불러오기 → 스트릭·체크·별자리가
      돌아온다. (복원 후 페이지가 스스로 새로고침된다.)
- [ ] 백업이 아닌 파일(아무 .json)을 고르면 "이 앱에서 내보낸 백업 파일이 아니에요"가 뜨고
      **기존 기록이 그대로 남는다.**
- [ ] 전체 삭제 후 홈·기록·도감이 전부 빈 상태로 돌아간다. **테마·팔레트는 유지된다.**
- [ ] 삭제 확인창에서 [취소]를 누르면 포커스가 [기록 전체 삭제] 버튼으로 돌아온다.
