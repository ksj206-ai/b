# 🌠 미니게임 ① 별 따기 (`starPick`) 설계

> 16단계(미니게임 이식)의 첫 게임. 참고: 이전 프로젝트 [BBB](https://github.com/ksj206-ai/BBB)의
> 🍓 열매 따기(`pinch`)를 밤하늘로 다시 설계한 것. 아트·구조는 가져오지 않는다.

## 0. 한 줄

떠도는 별을 엄지·검지로 집어 잠깐 유지하면 별이 손에 들어온다.
다 모으면 오늘의 별자리에 별이 켜진다.

---

## 1. 핵심 결정 — 게임은 새 보상이 아니라 `pinch_hold` 운동의 두 번째 얼굴

이 게임의 설계에서 가장 중요한 결정이다. **별 따기는 새로운 보상 체계를 만들지 않는다.
`pinch_hold` 운동을 하는 또 하나의 방법일 뿐이다.**

사용자는 핀치 집기를 두 가지로 할 수 있다 — 시범 손 따라하기(가이드) 또는 별 따기(게임).
어느 쪽이든 결과는 완전히 같다.

### 왜 이렇게 정했나

게임이 별을 독자적으로 켜면 두 가지가 깨진다.

1. **이중 계산** — `store.js:syncStarsToProgress`는 점등 수를 루틴 진행도에서 **역산**한다:
   `target = Σ plan[doneSlots]`. 게임이 따로 켠 별은 이 계산 밖에 있으면서 지워지지도
   않는다(그 함수는 부족분만 채운다). 켜진 별 수와 완료한 운동 수가 어긋난다.
2. **페이오프 가로채기** — 게임을 여러 판 하면 루틴을 완주하기 전에 별자리가 완성된다.
   "루틴 완주 → 별자리 완성"은 기획서 원칙 ③(감정 페이오프)의 핵심인데, 그 순간을 잃는다.

반대로 `routine.js:markRoutineDone(guideId)`는 **슬롯 인덱스가 아니라 guideId로** 완료를
기록한다. 게임이 끝날 때 `markRoutineDone('pinch_hold')` 하나만 부르면 가이드로 한 것과
글자 그대로 같은 경로를 탄다.

> **새 저장 스키마 0 · 새 보상 배관 0 · 이중 계산 0.**

### 성립 조건 셋

이 구조는 게임과 운동이 **물리적으로 같은 일**일 때만 정직하다. 셋 중 하나라도 깨지면
"게임 했으니 운동한 셈 쳐준다"가 되어버린다.

1. **게임이 판정·강도를 따로 정하지 않는다.** 임계값을 느슨하게 하거나 유지 시간을
   줄이면 게임이 적응형 강도를 우회하는 샛길이 된다. 사용자는 당연히 쉬운 쪽을 고르고,
   `adapt.doseLevel`은 무력해진다. → §2
2. **운동 위에 부담을 얹지 않는다.** 조준·타이밍·연타를 추가하면 같은 반복수가 더
   힘들어지고, 이번엔 아무도 게임을 안 고른다. BBB가 두더지 잡기에서 **망치를 자동으로
   움직인 것**이 이 판단이었다 — 사용자는 손목만 움직인다.
3. **루틴 연속 재생 안에 게임을 끼워넣지 않는다.** → 아래

### 진입점은 루틴 바깥에 둔다

`main.js`는 `routineMode` + `autoNextTimer` + `routineNextId`로 운동 6종을 자동으로 이어
재생한다. 그 4번째 차례에 다른 모듈·다른 화면으로 튀면 흐름이 끊긴다. 매번 "가이드로
할까 게임으로 할까"를 묻는 것도 원칙 ②(고민하게 만들면 안 한다)와 충돌한다.

> **루틴은 늘 가이드로 흐른다.** 게임은 홈/게임 탭의 별도 진입점이다. 게임으로 먼저
> 해두면 루틴이 그 슬롯을 완료로 보고 건너뛴다 — `nextRoutineExercise`가 미완료 첫
> 항목을 찾는 구조라 따로 손댈 것이 없다.

### 게임 하나 = 운동 하나 (1:1 고정)

핀치 게임이 `flex_ext`를 완료 처리해서는 안 된다. 그 지표는 손목 굽힘·폄을 보지
않았다. 게임은 **자기 대응 운동만** 인정한다.

### 재사용 / 신규

| | 무엇 | 출처 |
|---|---|---|
| ♻️ | 손 인식·카메라 | `tracking.js` — `startLoop` |
| ♻️ | 지표 (`fingers.pinch`) | `measurement.js` — `createWristTracker('live')` |
| ♻️ | 회수 판정 + 재장전 | `guide/stepEngine.js` — `createDetector('pinchHold')` |
| ♻️ | 반복수(적응형 반영) | `routine.js` — `getRoutineGuide('pinch_hold')` |
| ♻️ | 완료 처리·별 점등 | `routine.js:markRoutineDone` → `store.js:syncStarsToProgress` |
| ♻️ | 별자리 렌더 | `sky.js` — `renderSky(container, id, litIndices)` |
| ♻️ | 화면 껍데기 | `index.html:472` `#screen-game` · nav 🎮 버튼(현재 disabled) |
| 🆕 | 캔버스 루프 · 파티클 · 점수 HUD | `js/games/engine.js` |
| 🆕 | 별 따기 로직 | `js/games/starPick.js` |

## 2. 판정 — 새로 만들지 않는다

`createDetector('pinchHold', { thresh, holdMs })`를 그대로 쓴다.

```js
// stepEngine.js에 이미 있는 것
pinchHoldDetector({ thresh = 0.34, holdMs = 2000 })
//   snap = { detected, rel, comp, fingers }
//   fingers.pinch = dist(THUMB_TIP, INDEX_TIP) / palm
//   → pinch < 0.34 가 holdMs 지속하면 { justCounted:true }
//   → 놓으면 armed 복귀(재장전). 유지 중에는 progress 0~1 반환
```

- `pinch`는 **손바닥 길이로 나눈 값**이라 카메라와의 거리에 무관하다. 첫 게임으로 고른
  이유 중 하나 — 중립 캘리브레이션도, pose(보상동작) 의존도, 각도 부호 정규화도 없다.
- 판정기가 돌려주는 `progress`를 그대로 별에 차오르는 빛으로 쓴다. **게이지를 따로
  만들 필요가 없다.**

### 강도(dose)는 게임이 정하지 않는다

반복수는 `getRoutineGuide('pinch_hold', state, date)`가 준 값을 쓴다. 적응형 루틴
(`adapt.doseLevel`)과 순한 날 조정이 게임에도 그대로 적용된다.

게임이 자기 난이도를 따로 정하면, 게임이 **적응형 강도를 우회하는 샛길**이 된다.
같은 운동으로 인정받는 이상 강도도 같아야 한다.

유지 시간은 판정기 기본값 2000ms. (`pinch_hold`의 follow 스텝에 `holdSec`이 없어
`computeDose`는 `reps`만 조정한다 — `distributeDose`의 `baseHoldSec`은 null.)

## 3. 화면 — 오늘의 별자리는 무대가 아니다

**떠도는 별을 집는 것이지, 별자리의 별을 집는 것이 아니다.**

별자리의 별 하나하나를 직접 집게 하면 반복수와 슬롯 배정 별 개수가 어긋난다.
`distributeStars`는 별자리의 별(예: 7개)을 운동 6칸에 나누므로 `pinch_hold` 몫은
보통 1~2개인데, 운동 반복수는 5회다. 5회를 집었는데 별이 1개만 켜지면 어색하다.

그래서 이렇게 나눈다:

```
┌─────────────────────────────────────────────┐
│  밤하늘 (캔버스)                    ┌───────┐│
│                                     │오늘의 ││  ← 구석에 작게.
│        ✦                            │별자리 ││     진척 표시용
│              ✧  ← 지금 집을 별      │ 3/7   ││     (renderSky 재사용)
│                    (커지고 반짝)    └───────┘│
│    ✦                                        │
│                                             │
│   🐾 우주비행사 고양이                       │
│                              🤏 2 / 5        │
└─────────────────────────────────────────────┘
```

- 무대에 **떠도는 별** 몇 개가 흐르고, 그중 하나가 "지금 집을 별"로 지목된다.
- 집는 동안(`progress`) 그 별에 빛이 차오른다. 놓으면 빛이 스르르 빠진다(재장전).
- 1회 성공 → 별이 고양이 쪽으로 날아가 모인다. 파티클 + 짧은 소리.
- 반복수를 채우면 → `markRoutineDone('pinch_hold')` → **홈으로 돌아가면** 오늘의
  별자리에 슬롯 몫만큼 별이 켜져 있다. 기존 점등 연출을 그대로 탄다.

별자리 점등을 게임 안에서 재현하지 않는 이유: 점등의 주체는 `syncStarsToProgress`
하나로 유지해야 두 화면이 어긋나지 않는다.

## 4. 파일 구조

```
js/games/
  engine.js     # 공용 — rAF 루프, 파티클, HUD(반복수·힌트), 정리(stop)
  starPick.js   # 별 따기 로직만
```

`main.js`가 게임 화면 진입 시 **지연 로드**한다. 가이드 모듈과 같은 패턴
(`main.js:1228` 참고 — 화면별 dynamic import).

BBB는 게임 6종이 1160줄 한 파일에 모드 분기(`s.mode==="pinch"`)로 들어 있다.
그 구조를 따라가지 않는다 — 두 번째 게임부터 바로 무너진다.

## 5. 엣지 케이스

| 상황 | 처리 |
|---|---|
| **순한 날** | `gentleCourse = ['flex_ext','tendon_glide','finger_spread']`에 **`pinch_hold`가 없다.** 그날은 게임 진입점을 숨긴다. 억지로 열어두면 루틴에 없는 운동을 시키는 꼴 |
| **오늘 이미 완료** | 연습 모드로 연다. `markRoutineDone`을 부르지 않고 "오늘 몫은 다 했어요. 이건 그냥 재미로 🌠"라고 정직하게 알린다. 여분 판에 별도 보상(별가루 같은 새 재화)을 주지 않는다 — 새 스키마·새 화면이 늘고 원칙 ②의 마찰도 커진다. b는 성취를 쥐어짜는 앱이 아니라 "오늘 할 건 다 했다"고 말해주는 앱이다. 게임이 두셋 쌓여 정말 필요해지면 그때 도입한다 |
| 손 인식 실패 | 가이드와 같은 관대함 — **[건너뛰기] 항상 제공**. 실패로 막지 않는다 |
| 보상동작(`comp`) | `pinchHold` 판정은 `comp`를 보지 않는다. 핀치는 손목 자세와 무관하므로 그대로 둔다 |
| `prefers-reduced-motion` | 파티클·흔들림·반짝임 끔. 진행 표시는 남긴다 |
| 화면 이탈 | `engine.stop()` → `tracking.stopLoop()` + `stopCamera()`. 가이드 이탈 경로와 동일 |

## 6. 하지 않는 것

- **점수 등급·랭크를 노출하지 않는다.** BBB의 `levelTier()`(초급🌱/중급🌿/상급🌳)는
  가져오지 않는다. 기획서 원칙 ①(보이는 돌봄)과 `측정모듈_설계서_v2.md §7.2`
  ("게임 총점의 A~D 등급 노출 기각")에 어긋난다. 점수는 내부 신호로만.
- **제한시간을 두지 않는다.** 타이밍 압박은 관대함 원칙(④)과 충돌한다.
- **"실패" 개념을 두지 않는다.** 놓치면 그냥 다시 집는다.

## 7. 구현 순서

1. `#screen-game`에 캔버스 넣고 진입 배선 — nav 🎮 버튼 `disabled` 해제
2. `createWristTracker('live')` + `tracking.startLoop` 연결 (가이드와 같은 패턴)
3. `createDetector('pinchHold')` 물리고, 반복수는 `getRoutineGuide`에서
4. 떠도는 별 렌더 + `progress` 빛 차오름
5. 완주 → `markRoutineDone('pinch_hold')` → 홈에서 별 점등 확인
6. 파티클·소리·고양이 반응 (선택)

**1~3번까지가 배관 검증**이다. 여기가 서면 각도 기반 게임(별 줍기 = `flex_ext`,
유성우 받기 = `deviation`)은 판정기만 갈아끼우면 된다.

## 8. 다음 게임 예정 (같은 원칙)

| 지표 | 게임 | 대응 운동 |
|---|---|---|
| `rel` 굽힘/폄 | 별 줍기 (2층) | `flex_ext` |
| `rel` 좌우편위 | 유성우 받기 | `deviation` |
| `grip` 유지 | 별 점등 | `grip_hold` |
| `grip`/`spread` 반응 | 구름 걷기 | `finger_spread` |
| 손 모양 순서 | 별자리 잇기 | `tendon_glide` |

모두 같은 규칙을 따른다 — **게임은 대응 운동의 두 번째 얼굴이고,
완료는 `markRoutineDone(해당 guideId)` 하나로 끝난다.**
